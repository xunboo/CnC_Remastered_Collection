# Red Alert AI-Boost 4.0

[English version](README.md)

**源码更新日期：** 2026 年 10 月 9 日

**基础模组：** AI-Boost 3.2b，发布于 2022 年 11 月 3 日

本仓库包含 Red Alert 的 AI-Boost 模组、配置和创意工坊资源，以及配套的 Command & Conquer Remastered 游戏与地图编辑器源码。当前本地构建增加了针对可达薄弱区域的协同进攻、行军中的即时近距离交战、战斗单位数量领先超过 30 时立即发起的全面进攻、频繁袭击电厂的空军行动、大规模坦克部队对经济设施的优先打击、就近防御响应、更有针对性的兵种生产、更合理的矿车采矿与炼矿厂选择，以及资金充足时在安全矿区扩张并增加坦克产能。经济发展到一定程度后，AI 还会维持两座炼矿厂、两座战车工厂，以及合计两份 MCV／建造厂能力，并按需求增加矿仓容量。此前的地形渲染启动崩溃修复、可复现构建和回归检查脚本也包含在内。

可选的 LLM 战术桥接功能会导出实时战场快照，并接受严格类型约束的 `submit_tactical_plan` function call。把便携版 `LLMBridge.exe` 和已配置、由 Git 忽略的 `llm.ini` 放在模组的 `RedAlert.dll` 旁边，然后照常通过 Steam 启动 Red Alert。在本地单人遭遇战中，DLL 会检测已有桥接进程，或在后台启动 EXE；游玩时无需 PowerShell、脚本、Python 安装或环境变量。INI 用于启用功能并配置接口地址、完整认证信息、模型和请求头；没有 INI 时，LLM 控制保持关闭。示例配置使用 Cline Chat Completions，也支持 OpenAI Responses。当所有可用战斗组都为空时暂停请求，有部队可用后恢复。协议 2 将按真实时间计算的网络 `timeout` 与按模拟时间计算的 `plan_ttl_seconds` 分开，后者从 DLL 接受计划时开始计时。对象当前代次、实时路线、兵力安全检查和有界的真实时间快照历史仍决定计划是否被接受；更新时应同时更新 DLL 和 EXE。LLM 只控制一个电脑阵营，并保留原生交战、防御检查和自动到期机制。安装、离线 mock 模式及真实 function call 测试见[中文配置与协议指南](docs/LLM_TACTICS_CN.md)或[英文指南](docs/LLM_TACTICS_EN.md)。

逐局详细 JSONL 日志默认开启，独立于 LLM 控制。每场对局都会在已加载的 `RedAlert.dll` 旁的 `log` 文件夹中创建带时间戳的文件。同一文件记录完整世界快照、原生 AI 的生产／经济／采矿／战术评估、单位命令，以及过滤认证信息后的完整 LLM 请求和响应。DLL 和桥接程序通过共享文件锁写入；使用新的日志路径映射时，应同时更新这两个组件。字段、事件和存储行为见[逐局详细日志](docs/LLM_TACTICS_CN.md#逐局详细日志)。

## AI-Boost 4.0 的主要更新

**本地进攻 AI 更新：** 此更新记录在本地 Git 提交中，相对于仓库基线 `07d9ada8e7a58357e27312f659b3e034d7b6a2d3`（`Improve AI tactics, harvesting and base expansion`）。累计更新包含数量优势触发的全面进攻、更快的常规进攻、并行空军骚扰和大规模坦克部队的经济目标选择，也包含此前的遭遇交战、基础设施、经济恢复和犬舍修复。更早的战术、采矿和扩张改动也已纳入该提交。该提交保留在本地，尚未推送到 GitHub。

此前已发布的 AI 和渲染改动基于 [64c7037](https://github.com/xunboo/CnC_Remastered_Collection/commit/64c70377b7311bc00eb4aee4d8453d8f94aed361)，对比其父提交 [f1f0d42](https://github.com/xunboo/CnC_Remastered_Collection/commit/f1f0d42bc2dcd06d5d1df943c6150ab34bf307ae)。[查看完整代码差异](https://github.com/xunboo/CnC_Remastered_Collection/compare/f1f0d42bc2dcd06d5d1df943c6150ab34bf307ae...64c70377b7311bc00eb4aee4d8453d8f94aed361)。

| 领域 | 主要改动 |
| --- | --- |
| 集中进攻兵力 | 常规进攻波次在仍能组织至少四个战斗单位时，会把约 20% 的可用战力留在基地附近。地面与海军通过共享检查点，以已到达的单位分批推进，每批通常不超过 12 个单位。较大军队需要至少四个单位到位且估算战力达到 2,000；常规批次还必须满足目标和路线安全条件，必要时可以超过 12 个单位。75% 单位数量／80% 战力的集结检查只针对当前批次。新招募部队跟随前线，不扩大当前批次；前一批成员落后时，另一批已到位且足够强的部队可以继续推进。每个单位使用自己的最大移动速度和独立可达的编队目的地。数量优势触发的全面进攻和偶发的随机地面总攻都可以征用基地预备队。 |
| 保留前线与取消原因诊断 | 取消进攻后的单位在当前位置警戒，并通过对象当前代次保护前线预留，避免单位槽位复用造成误认。原生预备队处理会让它们保留在前线；新波次、目标切换和模型计划替换会在存活部队的前线附近设置集结点。已分配的防守部队保留命令，明确的撤退命令仍会执行。每次有效进攻的 `strike_cancel` 都记录原因、存活／就绪单位数量与战力、目标防御和响应兵力、阶段、检查点、路线进度、等待 tick 及保留的前线格。`strike_batch_ready` 记录每个新组成的推进批次。 |
| 近距离遭遇立即交战 | 地面部队和舰队每三个模拟 tick 检查一次接触，即每 0.2 个模拟秒。敌人进入原生射程，或能对本组成员开火时，会打断编队移动和战略撤退，让部队立即交战。每个单位优先选择主武器或副武器能够造成伤害的附近目标。共享的火力分配和生命值估算鼓励集中射击，同时减少过量攻击。已分配的防守部队使用相同的近距离目标选择；尚未投入行动的预备队会攻击已在射程内的敌人。原战略目标会保留，逃离射程的接触目标不再持续引开部队；行军部队会在前线重新集合，然后恢复路线或选择另一个薄弱区域。 |
| 数量优势触发全面进攻 | 相比全部活跃敌对阵营，存活且武装的机动单位数量领先严格超过 30 时，会在下一次三 tick 交战检查中触发；刚好领先 30 不满足条件。步兵、坦克、舰船和武装飞机计入，建筑、无武装运输单位、矿车和 MCV 不计入。脚本控制和补充弹药中的军事单位在双方统计中同样计入，但实际征用仍保留其原生控制。就绪且武器兼容的兵力可以出动，无需常规预备队、随机判定、进攻／经济计时器或局部战力否决。实际路线和武器允许时，地面、海军和空军可以同时出动。近距离交战仍优先，新就绪的增援每三秒加入；失去数量优势后恢复常规局部安全条件。 |
| 大规模坦克部队打击经济 | 可用主战坦克超过 20 辆时，优先选择可达的电厂、高级电厂和炼矿厂。备选目标使用最新敌军位置和防御信息。常规局部安全条件仍适用；经济区域不可达或过强时，改选其他薄弱目标。统计包含可用的受损坦克，不要求满足随机总攻的健康坦克门槛。 |
| 频繁空袭电厂 | 就绪飞机先寻找电厂和高级电厂，优先选择防空较弱的区域。单架弹药充足且估算战力至少为 500 的飞机也可以袭击暴露目标；小规模空袭无需满足地面组的四单位门槛。空袭与地面／海军进攻并行，保留补充弹药和满弹匣检查，并使用独立的八秒重试计时器。没有可安全攻击的电厂时，会考虑其他武器兼容的薄弱目标。 |
| 随机地面总攻 | 至少 20 辆可用主战坦克的生命值达到 50%，且总估算战力至少为 10,000 时，每 30 个模拟秒进行一次概率为 25% 的原生确定性随机判定。成功发动后有三个模拟分钟的冷却期，也可以从已有波次的当前前线增援。实际征用且路线可达的部队必须满足相同的坦克门槛。可用地面护卫不受常规预备队保留限制，但矿车、MCV、特殊车辆和脚本队伍保留原任务。基地正在遭袭时推迟总攻。可达接近路线、局部优势、路线安全和常规集结条件仍决定能否发动；敌方建筑和机动单位均可作为目标。 |
| 薄弱区域与可达接近路线 | 敌方建筑和部队位置共同参与目标评分。可通行地形、建筑、墙体、水域和地图边界决定可达性。加权路线倾向于绕开密集防御、从侧翼接近。常规波次拒绝无法绕开的危险瓶颈。目标／路线扫描每两个模拟秒运行一次，备选目标使用六秒的评分滞回，防御响应每秒刷新。明确的数量优势全面进攻仍保留真实路线和集结要求，但在数量优势失去前绕过局部战力否决。 |
| 优势判断与持续施压 | 常规地面／海军进攻需要四个战斗单位、2,000 估算战力、达到附近可达机动增援的 115%，以及局部防御的 150%。远处的敌军主力不会否决局部进攻。敌方仍有建筑时，常规波次也可以选择暴露的敌方单位。新防御工事或增援可能导致波次改向或撤退。成功进攻的部队从前线继续施压。武器检查包含对目标装甲是否能造成有效伤害。 |
| 就近防御与暴露矿区 | 最多三个遭袭区域分别获得附近可达的响应部队，包括对矿车和行进中 MCV 的保护。射程内正常工作的防御塔可以覆盖袭击，无需强制派出机动防守单位。最多三个敌人的袭击使用 110% 的估算战力余量，分配足够响应兵力后停止。可用地面／海军战斗单位至少为八个时，每个小型遭袭前线通常最多分配四分之一兵力。关键设施直接受袭可以超过该预算，较小军队则可以使用全部必要响应兵力。未得到保护的关键资产会阻止新的进攻，但可选矿仓受袭不会冻结全军。新防御塔优先覆盖已受威胁或敌人可能接近的方向，同时遵守建造距离并保护炼矿厂出口。 |
| 重型武器响应与经济优先级 | 大量敌方装甲提高主战坦克和重型武器的生产权重，降低反步兵车辆权重，并在有坦克产能时限制步兵护卫支出。经济扩张需要正常工作的矿车、足够电力和资金，以及可行的防御。最后一座建造厂丢失后仍可恢复。可选支出前，会预留已承诺生产的资金及新前哨炼矿厂／电力预算。 |
| 空军与海军武器兼容性 | 舰船以舰队方式集结，鱼雷武器获得兼容的海上目标。直升机可以集结进攻，满弹的固定翼飞机从附近机场共同出击。补充弹药、停靠飞机、无限弹药设置和副武器防空均有明确处理。敌方建筑被摧毁后，其剩余无武装 MCV 仍可被选为目标。 |
| 附近富矿与矿区拥堵控制 | 自动矿车比较可达地面路线和其他矿车已认领的矿点。在附近两至四个等效路线格的范围内，优先比较经过拥堵调整的单次采集收益，再比较矿石总量，因此附近少量宝石也可以优先于更厚的普通矿。采集收益相同才比较丰富程度。已在采矿的矿车每三个模拟秒重新检查，不必等当前矿格耗尽；相同收益矿点的丰富程度提升必须同时超过 25% 和一次采集收益，才值得移动。切换时保留已有矿载。拥挤矿区降低优先级，占用矿格直接排除，远处或不可达宝石不会压过附近矿石。返程矿车从当前位置重新扫描，不再自动回到记忆中的远处矿区。`harvester_ore_selected` 记录来源／目标矿量、采集收益、占用预留数、路线距离和选择原因。 |
| 可达炼矿厂与独立等待位置 | 选择炼矿厂时使用实际南侧卸矿入口、路线长度、当前卸矿／无线电占用及驶入矿车预留。附近空闲炼矿厂通常优于忙碌炼矿厂，但远处空闲卸矿位不会自动压过近得多的队列。等待矿车使用距入口两至四格的独立位置，到位后保留等待点，并每三个模拟秒重新评估。变化很小且基本等价时保留当前选择。 |
| 受损矿车自保 | 自动矿车确实受到敌人伤害、携带任何矿石且生命值不高于 `ConditionRed`（默认 25%）时，提前返厂，并把未满的矿载交给原生卸矿流程。撤退优先于追逐步兵进行碾压。明确移动、维修命令、脚本队伍、已接受的停靠和卸矿仍保留控制权。 |
| 中后期基础设施最低数量 | 从五个模拟分钟开始，空闲建造决策持续检查至少两座炼矿厂和两座战车工厂。已启用且策略上限为一座的类别获得两座的有效最低值。资金充足的第二座工厂不再依赖当前军队是否还有单位上限空间或是否采用地面策略。类别为零、科技、有效收入、足够工作矿车、预留资金和总建筑上限仍然适用。第二座建筑被摧毁后会重新考虑补建。选址缓存十个模拟秒，相关基础设施数量改变时失效；原生放置流程会重新检查位置。 |
| 合计两份基地能力 | 从五个模拟分钟开始，建造厂与未部署 MCV 的合计最低目标为两个。一座建造厂加一辆 MCV，或两座建造厂，都满足要求。正数基地上限的有效值至少为二。第二基地可以使用已获服务的安全密集矿区，但仍要求工厂路线可达、建造厂相距至少 12 格，并有合法的炼矿厂／电力后续位置。购买 MCV 仍需要两辆正常工作的矿车、六个等效防守单位、科技、电力及完整的购买／前哨／战斗预算。缺少维修厂时可以为其提供预算。进一步扩张遵守原有远处矿区策略和上限。 |
| 按预算增加矿仓 | 已有资金支持的炼矿厂、战车工厂和扩张前置设施投资优先于储存。现有矿容量加现金不足以保留本来已符合条件的工厂或 MCV 预算时，资金充足的矿仓优先于可选防御和多余电力。容量会增加到足以达到该预算，同时在建筑上限内为目标投资留出空间；其他储存请求保留常规原生建造优先级。原生采矿收入账本包含 AI 加成和容量满后被丢弃的矿石，使用六个十模拟秒时间桶估算滚动收入。扣除未付生产承诺后，储存还要覆盖未来 20 秒的收入。可选建造前预留补充部队、经济恢复和行进中 MCV 的资金；严重缺兵但资金充足时，可以在补兵的同时建造必要矿仓。矿业正常且战斗预算充足时，作战车辆优先于额外的可选矿车。低资金时保留可行的恢复矿车和炼矿厂预算，新请求不会重复扣款。没有固定 12 座矿仓、建筑百分比或地图面积配额；预测收入、增长预算、现有容量、剩余总建筑空间和合法位置决定需求。卸矿／工厂出口和矿车路线继续受到保护。只有满仓而没有近期收入，不能成为扩张依据。 |
| 资金充足时在安全矿区扩张 MCV | 可选 MCV 需要两辆正常工作矿车、足够电力、六个等效防守单位，以及扣除未付生产后足以支付 MCV、前哨首座炼矿厂和恢复／战斗缓冲的资金。安全可达矿区和合法后续建造空间决定扩张，远处敌军数量不会否决它。有可行前哨时，缺失的维修厂可以作为 MCV 前置设施获得预算。密集矿区按富裕程度、路线、采矿认领和敌方危险评分。 |
| 安全部署与路线控制 | MCV 沿安全地面路线的短检查点移动，定期检查威胁和部署位置，到位时立即检查。新威胁触发新路线或新位置；已进入危险区域的 MCV 可以向安全的基地地形撤退。检查包含墙体、水域、斜向切角、建筑占地和实际工厂出口。首座建造厂丢失后的恢复不受可选扩张条件限制。 |
| 远处采矿路线附近的炼矿厂 | 可达矿区路线至少为 16 格时，可以考虑更近的炼矿厂，要求卸矿入口距矿区路线不超过八格，且至少节省八格路线。合法的炼矿厂延伸先于购买 MCV；否则，资金充足的资源前哨可以提供建造距离。新建造厂和炼矿容量过载也提高炼矿厂优先级。 |
| 更多坦克工厂 | 在中后期两座工厂最低目标之外，资金充足的地面策略军队，或面对敌方装甲的军队，可以在炼矿厂／矿车能力足够、有效坦克生产仍低于上限时增加战车工厂。选址保持出口可通行，并减少炼矿厂拥堵。原生工厂数量带来的建造速度加成仍适用；Aftermath 开启且快速建造关闭时，投资止于两座工厂。首座工厂被毁后的恢复会在需要时预留替代矿车资金。 |
| 自适应兵种生产 | 生产响应敌方装甲、步兵、飞机和防御建筑。防空与攻坚单位获得相应权重，支援和爆炸车辆在作战部队中的比例受到限制。 |

本地模组包位于 [WorkshopContent/AIBoost](WorkshopContent/AIBoost)。原始订阅模组的常见安装路径为：

```text
C:\Program Files (x86)\Steam\steamapps\workshop\content\1213210\2221741447\AIBoost
```

AI 设置位于当前模组的 [CCDATA/AIBOOST.INI](WorkshopContent/AIBoost/CCDATA/AIBOOST.INI)。附带配置使用 `AIStrategyMode=1`、`AIAttackFirstTime=5` 和 `AIAttackInterval=5`。

- `AIStrategyMode=0` 启用自动策略选择及由敌方反制推动的策略转换。
- `AIStrategyMode=2` 在基地有合法海军建造位置时允许主动生产海军。请求的策略不可行时，回退到混合动态模式。
- 遭遇战进攻机会每两个模拟秒检查一次。`AIAttackInterval=5` 对就绪的新地面／海军波次表示十个模拟秒；其他正值每单位对应两秒，限制在 4–15 秒。零间隔或 `SpeedRush` 使用两秒。常规波次在一个模拟分钟后具备发动资格；数量优势全面进攻绕过开局延迟和进攻／经济计时器。独立空袭机会间隔为八个模拟秒。真实时间受游戏速度影响。
- 近距离交战和战斗单位统计每三个模拟 tick 检查一次。战斗单位数量领先严格超过 30 时，所有就绪且兼容的地面／海军／空军出动，不保留预备队，也不进行随机判定，但保留路线、集结和近距离战斗优先级。敌方数量合并全部敌对军队。就绪坦克超过 20 辆时优先攻击电力／炼矿区域。既有随机地面总攻使用独立默认条件：至少 20 辆生命值达到 50% 的坦克、可用弹药、战力 10,000，每 30 秒进行一次 25% 概率判定，并有三分钟冷却。这些策略是 `REDALERT/AITACTICS.H` 和 `REDALERT/AITACTICS.CPP` 中的源码常量，没有新增玩法 INI 键。
- 战术发动与集结门槛位于 `REDALERT/AITACTICS.H` 和 `REDALERT/AITACTICS.CPP`。地面／海军批次通常最多含 12 个到位成员；军队至少有四个成员时，批次至少需要四个成员和战力 2,000，常规目标／路线安全可能要求更大批次。飞机保留自己的出击／集结规则。取消后的波次可在五个模拟秒后从存活部队前线重新评估；受阻的数量优势进攻每三秒重试。集结点或检查点停滞、持续 40 个模拟秒没有进一步集结进展时取消，记录原因，并让幸存部队留在前线警戒。既有科技和生产类别上限仍适用。开局遭遇战时机由上述机会控制器决定。
- 中后期最低数量在五个模拟分钟时启用：两座炼矿厂、两座战车工厂，以及合计两座建造厂／MCV。建造决策持续重新检查实时数量，成本较高的基础设施选址在十秒经济扫描或设施数量变化时刷新。已启用的一座策略上限提高到最低两座；零类别和总建筑上限仍适用。坦克工厂需要有资金支持的生产和至少两辆正常工作的矿车。
- 矿石储存使用原生 `Tiberium`、`Capacity` 和采矿收入账本。扣除生产承诺后，剩余容量不能覆盖未来 20 秒收入时增加储存；或者保留现金加总矿容量无法达到本来已符合条件的工厂／MCV 预算时，也增加储存。后一种情况给予资金充足的矿仓高于可选防御和多余电力的优先级，并在建筑上限内为目标投资留出空间。军事薄弱会预留增援资金，而非停止建造：现金足够时可以同时支持两个队列。矿仓数量没有固定配额，每次请求受成本、电力、总建筑上限、合法空间和交通可达性约束。收入窗口和预测间隔是 `REDALERT/AIEXPANSION.H` 中的源码常量，没有修改玩法 INI 值。
- 经济控制器适用于启用基地建造的电脑遭遇战阵营。资源／位置扫描每十个模拟秒运行一次；行进中的 MCV 每五秒和到达检查点时重新检查，目的地最多距当前路线四步，停滞 20 秒后重新考虑移动。可选扩张决策间隔为两个模拟分钟。
- 新矿区前哨需要价值至少为炼矿厂价格两倍的密集矿区、从实际战车工厂出口出发的直接安全地面路线，以及建造厂、炼矿厂和电力设施的合法位置。可选购买的 MCV 还需要科技／前置设施、两辆实际工作矿车、足够防御和电力，以及 MCV、首座炼矿厂和预留资金。已有资金支持的安全前哨时，可优先补建缺失维修厂；防御使用当地位置安全和最低驻军，不以全地图敌军战力否决。首座建造厂恢复单独处理。
- 生产预算扣除建筑、车辆、步兵、飞机、舰船五类的未付余额和新请求。低资金保护可行的采矿恢复；可选建造预留缺失部队和行进中 MCV 的后续资金。采矿正常且战斗资金充足时，严重缺兵的军队先用战车工厂生产作战车辆，再考虑可选矿车。两项预算都足够时，炼矿厂恢复和有资金支持的战斗生产可以并行。资金充足的经济增长优先于相对真人的基地规模限制；为解锁合格增长预算所需的储存也有同样优先级，其他储存请求则先完成剩余原生设施需求。`AIMaxBuildings`、类别上限、科技和合法放置仍适用。储存决策记录增长预算、现金上限，以及增长需求是否给予矿仓优先级。
- `AIMaxConYardsAndMCVsBasic/Mix/Naval`、`AIRefineryLimitOverwrite` 和 `AIWarFactoryLimitBasic/Mix/Naval` 在最低两座以上仍保留配置上限；明确关闭的零类别仍关闭。Aftermath 单位开启且 `AIAftermathfastbuild=false` 时，原生建造速度在两座战车工厂之后不再提升，规划器不会继续为提速购买工厂。旧的 `AIAllowLastMCVToDoSecondBase`／`AIAllowMoreMCVsToExtraBase` 路点／超时空传送扩张路径用于战役行为；遭遇战扩张使用安全资源位置。
- `HarvesterOptimizeEnabled=1` 为 AI 和真人矿车启用新的自动采矿逻辑。空闲和采矿中的矿车在附近可达矿点之间优先比较采集收益，再比较丰富程度，并计入拥堵惩罚。采矿中的矿车每三个模拟秒重新检查，切换到更好的附近矿点时保留已有矿载。明确命令和原生停靠／卸矿保留控制权。关闭优化时，`AIHarvesterMemoryValue` 及旧 thrashing／communalism 权重设置用于旧选择方式。
- `HarvyOptimizeUnloadWaitWeight` 仍表示以等效路线格计的排队成本，默认为六格。即使原生 A-star 关闭，新控制器也统一使用格数。等待矿车每三个模拟秒重新评估；自动采矿移动十秒没有进展时可重新扫描。`ConditionRed` 控制提前返厂的生命值门槛。

## 从对局日志绘制军队与资金曲线

[Python 日志查看器](SCRIPTS/plot_ai_log.py) 打开文件选择窗口，绘制日志记录期间双方军队数量和可用资金。在 Windows 中，从仓库根目录运行：

```powershell
./SCRIPTS/Run-AILogViewer.ps1
# Open a particular log immediately:
./SCRIPTS/Run-AILogViewer.ps1 -LogPath 'C:\path\to\match.jsonl'
```

启动器需要带 Tkinter 的 Python 3.10+，可在已有时使用 Codex 附带的 Python。首次使用若缺少 Matplotlib，会下载到 `build/log-viewer-deps/`，让绘图依赖保留在仓库本地。使用独立 Python 安装时，等价命令为：

```powershell
python -m pip install -r SCRIPTS/requirements-log-viewer.txt
python SCRIPTS/plot_ai_log.py
```

通过下拉框选择 AI 和对手；包含多场对局的文件有单独的对局选择器。工具栏支持缩放、平移和恢复全局范围。鼠标移到图上可查看最近的记录样本。可以将图保存为 PNG、SVG 或 PDF，也可以将原始数量和资金导出为 UTF-8 CSV。默认导出目录为 `build/log-plots/`。

军队数量统计已部署、存活且活跃的车辆、步兵、飞机和舰船，包括支援单位；排除矿车（`HARV`）、MCV、建筑，以及 limbo 状态的对象，例如尚未完成生产的单位和运输中的乘员。统计类别选择器可以改为包含全部已部署机动单位，或只对比一个类别。资金曲线来自快照中的可用 `credits`，不是累计收入。横轴使用模拟分钟（`sim_frame / ticks_per_second / 60`），游戏速度变化不会扭曲时间轴。

查看器流式读取 JSONL，只保留快照汇总值，以支持大型日志。它排序快照、合并重复帧、分隔对局，把缺失数据保留为空缺，并报告损坏的快照记录。自动玩家选择排除地图中立阵营和未使用阵营。日志没有记录联盟成员关系，团队对局需核对所选对手。曲线范围只覆盖文件内实际存在的快照，不能重建日志开始前或结束后的时间。要刷新仍在写入的对局，重新打开文件。

不打开窗口的导出方式：

```powershell
python SCRIPTS/plot_ai_log.py --input 'C:\path\to\match.jsonl' --export build/log-plots/match
# Specify both houses, and optionally a match ID or counting category:
python SCRIPTS/plot_ai_log.py --input 'C:\path\to\match.jsonl' --ai 13 --opponent 12 --metric army --export build/log-plots/match
```
